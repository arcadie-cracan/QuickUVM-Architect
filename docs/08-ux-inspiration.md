# 08 — UX inspiration: move the gesture onto the canvas, keep the YAML

*Research synthesis, October 2026 — five parallel source surveys (MBSE/UML/SysML, EDA SoC assembly and verification tools, node-based editors and diagramming libraries, GUI builders, VS Code diagram editors with text sync); a translation of the Romanian original delivered in chat.*

No VS Code extension and no standalone application closes the loop that QuickUVM Architect closes — RTL schematic → selection on the diagram → surgically edited YAML → generated UVM testbench — but each of the five families surveyed has solved exactly one piece of it, and their synthesis yields a precise diagnosis: the tool is not "insufficiently visual", it is **insufficiently direct**. The architecture is already at the head of the pack — the surgical edits via `WorkspaceEdit` outdo draw.io and KIE Tools, which replace the whole document and carry `TODO`s in their code about it ([draw.io](https://github.com/hediet/vscode-drawio/blob/master/src/DrawioEditorProviderText.ts), [KIE](https://raw.githubusercontent.com/apache/incubator-kie-tools/main/packages/vscode-extension/src/DefaultVsCodeKieEditorChannelApiImpl.ts)), positions in a sidecar are the mainstream choice of model-first tools ([Structurizr](https://docs.structurizr.com/ui/diagrams/manual-layout)), and persisted drag/flip/fold outdo Kaoto, Workflow Studio and Composer, which offer only auto-layout. What is missing is exactly what HCI calls directness: the gesture starts from a button in the sidebar and from a quick pick, not from the object on the canvas (articulatory distance), and its effect lands as an invisible YAML edit and a re-render, with no continuous representation of the action — a rubber-band wire, a highlighted legal target, the ghost of the node being created — and without the code that has just changed (evaluation distance) ([Hutchins, Hollan & Norman](https://vis.csail.mit.edu/classes/6.859/readings/pdfs/Hutchins-DirectManipulationInterfaces.pdf)). All the mature editors have converged on the same answers: creation from the thing you are holding in your hand (Blueprints, Blender 3.1, Houdini, Simulink), legality visible *before* the click (Vivado, Simulink R2018b, Platform Designer), state drawn *on* the graph (LabVIEW, Houdini, Node-RED, Cameo) and the generated code *next to* the diagram with element↔line traceability (Embedded Coder/HDL Coder, Umple). All of them can be implemented with SVG + DOM events + native VS Code APIs, on top of the existing YAML mutations — none requires a diagramming framework and none touches the invariants already decided. The report below proposes **25 recommendations** in three tiers (9 quick wins, 9 medium, 7 large), each with the borrowed pattern, the source, the mapping onto the existing mechanics, the complexity and the risks, followed by the list of what must *not* be copied and the questions that remain open.

## The landscape: nobody closes the schematic → YAML → UVM loop, but each family has solved a piece

The basic question gets an answer that is negative and, at the same time, encouraging. On the EDA axis, the closest conceptual relative is "Generate Testbench System" in Platform Designer, which instantiates the system and attaches a BFM to each *exported* interface, matched by type — the testbench is derived from the DUT boundary, not drawn ([Intel, Generating System Testbench Files](https://www.intel.com/content/www/us/en/docs/programmable/683609/24-1/generating-system-testbench-files.html)); Synopsys VC AutoTestbench does the same thing starting from IP-XACT, with "a single button press" ([Synopsys](https://origin-www.synopsys.com/verification/soc-verification-automation/vc-autotestbench.html)). No commercial tool, however, documents the gesture *selection on the canvas → agent*: **"lasso pins → Agent from selection" is already more visual than any shipped tool**, and the industry convention is complementary — type-driven proposal. The testbench generators (Easier UVM, UVMF/`yaml2uvmf`, `uvmgen`) are flat key-value specifications with form- and wizard-shaped front ends ([Doulos](https://www.doulos.com/knowhow/systemverilog/uvm/easier-uvm/easier-uvm-code-generator/easier-uvm-code-generator-reference-guide/), [Verification Academy](https://verificationacademy.com/forums/uvm/how-generate-uvm-code-yaml-code)); the only precedent with a dedicated GUI, the Tkinter builder presented at DVCon, has two ideas nobody else has had — a **monitor × scoreboard connectivity matrix** and incremental regeneration "Stitch / Create & Stitch" ([DVCon, Novel GUI Based UVM Test Bench Template Builder](https://dvcon-proceedings.org/wp-content/uploads/Novel-GUI-Based-UVM-Test-Bench-Template-Builder.pdf)). On the *visualization* side, AMIQ DVT draws the UVM environment exactly like QuickUVM — containment + labeled TLM edges — including in its VS Code edition, with "Go to Type"/"Go to Create Call" from right-click and `hide|show|color` × element kind × regex filtering rules ([AMIQ DVT, VS Code](https://eda.amiq.com/documentation/vscode/sv/toc/diagrams/uvm-components-diagrams.html)); but DVT is read-only and warns explicitly that the diagram from source "might not be completely accurate", offering a simulation-generated `.chd` for the complete picture ([AMIQ DVT, Eclipse](https://eda.amiq.com/documentation/eclipse/sv/toc/diagrams/uvm-components-diagrams.html)) — an independent validation of Architect's "ghost" convention for inferred components. The rendering stack is neither a differentiator nor a problem: netlistsvg uses elkjs for SVG schematics from Yosys JSON ([netlistsvg](https://github.com/shuckc/netlistsvg)), TerosHDL has a schematic viewer in VS Code ([vscode-terosHDL](https://github.com/TerosTechnology/vscode-terosHDL)), so the feeling of "not visual enough" does not come from the ability to draw.

The SoC assemblers — Vivado IP Integrator, Platform Designer, SmartDesign — are the closest relatives in terms of *gesture*. All three converge on the same triad: a searchable catalog instead of a free palette, drag from a pin with the *legal* targets highlighted (a green check mark in Vivado, a crosshair cursor in SmartDesign, a hollow circle in Platform Designer) and, above all, **automation that proposes connections**: Vivado's green "Run Connection Automation" banner "monitors the design as you work, so new automation options appear as you add IP", and after applying, the connections are "highlighted in the diagram" ([UG994, Designer Assistance](https://docs.amd.com/r/en-US/ug994-vivado-ip-subsystems/Using-the-Designer-Assistance-Feature)). User complaints do not target the canvas but the hidden state: XML `.bd` files "meaningless to compare", Tcl scripts that must be re-run at every checkout, "considerable amounts of time hacking the block-diagram / system raw files" ([FPGARelated](https://www.fpgarelated.com/thread/82/why-vendors-insist-on-creating-block-diagram-editors), [r/FPGA](https://redlib.ssps.io/r/FPGA/comments/1an0lt9/it_cant_be_that_hard)). This is exactly the cluster of problems that the invariant "YAML is the source of truth, surgical edits" already solves — but solves *in the architecture*, not *visibly*.

In VS Code, all the mature tools have converged on the shape QuickUVM already has: a `CustomTextEditorProvider` registered as the *default* editor for a file-name pattern, with the text editor reachable through "Reopen With" or a "Return to Default Editor" button ([AWS Workflow Studio](https://aws.amazon.com/blogs/compute/introducing-an-enhanced-local-ide-experience-for-aws-step-functions), [Kaoto](https://docs.redhat.com/en/documentation/red_hat_build_of_apache_camel/4.14/html-single/kaoto_camel_designer/index)). The difference is in what they do *behind the scenes*: Workflow Studio converts "YAML files ... to JSON for editing and back to YAML before saving" and synchronizes only on save; draw.io writes `workspaceEdit.replace(new Range(0, 0, document.lineCount, 0), …)` with the comment `// TODO diff the new document with the old document and only edit the changes`; KIE admits "This shouldn't be a replace all the time. More conscious changes lead to better undo/redo stack"; Karavan registers no custom editor at all and writes the file directly with `fs`, losing undo completely ([Karavan](https://github.com/apache/camel-karavan/blob/main/karavan-vscode/src/designerView.ts)). On gestures, the YAML-flow family grows diagrams through "+" on edge hover, Prepend/Append/Replace menus on the node and a modal catalog; Kaoto made drag reordering a default feature only in 2.10 (March 2026), arguing that the alternative is "tedious manual editing or complex refactoring" — and their blog says explicitly that it does *not* describe dragging from the catalog onto the canvas ([Kaoto, Drag and drop](https://kaoto.io/blog/2026/drag-and-drop/)). Drawing connections between ports exists only in the generic frameworks that own the model (GLSP with "Element Type Hints" and "Ghost Elements" ([GLSP](https://github.com/eclipse-glsp/glsp)); IntelliJ "Edge Creation mode" ([JetBrains](https://www.jetbrains.com/help/idea/class-diagram.html))) — exactly the stack rejected in D22/D23. The element-level diagram→text link is rare: draw.io "Code Link" performs a symbol search on double-click ([draw.io](https://github.com/hediet/vscode-drawio)), and the native Markdown preview puts "a light gray bar in the left margin" at the selected line and jumps to the nearest line on double-click ([VS Code, Markdown](https://code.visualstudio.com/docs/languages/markdown)). **A `yaml` CST → `Range` with `showTextDocument(..., {viewColumn: Beside})` would put Architect ahead of every VS Code tool in the survey.**

The MBSE family answered long ago the question "why does it feel like filling in forms": the dominant pattern **is not drag from a palette, but creation from the selected element**. Cameo has the "smart manipulator toolbar" — you pick the relationship, a click on empty canvas "creates that element along with the relationship" ([MagicDraw](https://docs.nomagic.com/x/CwomC)); Enterprise Architect has the "Quick Linker", an arrow on the corner of the selected element, with the keyboard equivalent Ctrl+Shift+Arrow and the "Edit Object on New" option that can be disabled for "rapid modeling" ([Sparx EA](https://sparxsystems.com/enterprise_architect_user_guide/16.0/quick_links.htm)); Visual Paradigm has a single icon in the corner of each shape, with the catalog ordered by frequency of use ([VP](https://s.visual-paradigm.com/support/documents/vpuserguide/1283/27/6253_resourcecent.html)). Simulink went further: double-click on the canvas and type the block name — MathWorks says it is "significantly faster than dragging blocks from the Simulink Library Browser" ([Predictive Quick Insert](https://blogs.mathworks.com/simulink/2019/01/16/predictive-quick-insert)) — and since R2018b "if you click on a port, compatible ports are highlighted, and you can click on one of them to make the connection. No more need to hold the mouse and drag" ([R2018b](https://blogs.mathworks.com/simulink/2018/09/24/whats-new-in-r2018b/)). On model↔code, Embedded Coder and HDL Coder are the gold standard: "The Code view opens by default to display the generated code next to the model", a click on a block highlights the lines, the comments in the code are hyperlinks back to the block, and a report explicitly lists the *untraceable* blocks ([Embedded Coder](https://www.mathworks.com/help/ecoder/ug/trace-simulink-model-objects-in-generated-code.html), [HDL Coder](https://www.mathworks.com/help/hdlcoder/ug/traceability-report.html)). UmpleOnline does the reverse, and live: "edit UML diagrams graphically and watch the Umple textual code being written in real time", and a click on a state "will highlight its code in the text pane" ([UmpleOnline](https://cruise.umple.org/umpleonline/), [Umple releases](https://umple.org/releases)).

Node-based editors are where directness has been polished the hardest, because their users spend hours a day in them. The common denominator of those that "feel direct": you create the node *where the cursor already is* and, above all, *from the thing you are holding in your hand* — you drag a wire into empty space and a search filtered by the origin pin opens, and the new node arrives already connected (Blueprints: "the nodes will automatically become connected" ([Connecting Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/connecting-nodes-in-unreal-engine)); Blender 3.1: "When dragging a node link over empty space, a new search menu allows quickly connecting a node with a compatible socket" ([Blender 3.1](https://developer.blender.org/docs/release_notes/3.1/nodes_physics/)); Invoke: "results filtered to compatible nodes only" ([Invoke](https://invoke.ai/features/workflows/adding-nodes/)); React Flow ships the "Add Node On Edge Drop" example on `onConnectStart`/`onConnectEnd` ([React Flow](https://reactflow.dev/examples/nodes/add-node-on-edge-drop))). The libraries expose the same mechanics as parameters: `connectionRadius` 20 px and `isValidConnection` in React Flow ([API](https://reactflow.dev/api-reference/react-flow)), `snapLinks` + `markAvailable` + `validateConnection` in JointJS ([JointJS](https://docs.jointjs.com/api/dia/Paper/)), `portGravity` 100 px in GoJS ([GoJS](https://gojs.net/latest/api/symbols/LinkingBaseTool.html)). State lives on the graph: LabVIEW's broken wire is a "dashed black line with a red X" ([NI](https://www.ni.com/getting-started/labview-basics/debug.htm)), Houdini has a row of badges under the node name with a "Large" variant visible when zoomed out ([Houdini badges](https://www.sidefx.com/docs/houdini/network/badges.html)), Node-RED puts "A blue circle above a node means it has undeployed changes" ([Node-RED](https://nodered.org/docs/user-guide/editor/workspace/nodes)).

GUI builders give the most important structural lesson: **the declarative, one-way-generation model has survived for decades; the bidirectional one over general code was withdrawn.** Qt generates code from `.ui` at build time through `uic` ([Qt](https://doc.qt.io/qt-6/designer-using-a-ui-file.html)), Glade produces XML loaded at runtime, Delphi parses `.dfm` on save — the same model as YAML → `quick-uvm`. Xcode 11 had promised editing "the exact same Swift code file you can also edit by hand"; in Xcode 26 the SwiftUI inspector was removed, an Apple engineer confirming "Yes, the SwiftUI Inspector feature was removed in Xcode 26", and users observing "Looks like Xcode is less and less WYSIWYG" ([Apple Developer Forums](https://developer.apple.com/forums/thread/800946)). What remains valuable from Xcode is the half that QuickUVM can have without the risk of the other: *seeing* the code change while you gesture. Android Studio offers the concrete "Split" model with Code and Design simultaneously, an Attributes panel structured "Declared / Layout / Common / All" and red/orange highlights in the fields and in the Component Tree ([Android, Layout Editor](https://developer.android.com/studio/views/layout-editor)); the Flutter Property Editor labels each property "set" or "default" and has a "Set only" filter ([Flutter](https://docs.flutter.dev/tools/property-editor)); Figma UI3 documents reversals after feedback — controls hidden behind icons "slowed down workflows because it forced users to wait for a tooltip", floating panels "cramped the canvas", "Speed is a feature" ([Figma, UI3](https://www.figma.com/blog/our-approach-to-designing-ui3/)).

| Family | Closest to QuickUVM Architect | How close | What it lacks compared to Architect |
|---|---|---|---|
| EDA — SoC assembly | Vivado IPI, Platform Designer, SmartDesign | wiring gesture + proposed automation; HDL generated as "output products" | do not produce a testbench from selection; non-diffable files |
| EDA — verification | Platform Designer "Generate Testbench System", DVCon Tkinter builder, AMIQ DVT | BFM per exported interface; monitor×scoreboard matrix; UVM diagram in VS Code | DVT is read-only; the builder is forms; nobody has selection on the canvas |
| VS Code, YAML as source | Workflow Studio, Kaoto, KIE, draw.io | same packaging (default `CustomTextEditorProvider`) | whole-document replace / JSON round-trip; no persisted positions; no element→text link |
| MBSE / UML / SysML | Simulink + Embedded/HDL Coder, Umple, Cameo, EA | code next to the model with traceability; creation from selection | they own the model; explicit synchronization (SysML v2) |
| Node-based editors | Blueprints, Blender, Houdini, Node-RED, React Flow | the complete directness vocabulary | no hand-editable textual source of truth |
| GUI builders | Qt Designer, Android Layout Editor, Flutter Property Editor | same declarative model; structured inspector; text/design split | do not generate verification code; different domain |

## The patterns that transfer: creation at the point of attention, legality before the click, state on the graph, code next to the diagram

Nine pattern clusters emerge from the five notes, each supported independently by several families — which is a better signal than any isolated study. The first and most consistent is **creation at the point of attention, with the context already applied**: Blueprints filters the menu "based on the current context" and places the new node already connected ([Placing Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/placing-nodes-in-unreal-engine)); Houdini places the new node "wired to that connector" when you press Tab on a connector ([Houdini wiring](https://www.sidefx.com/docs/houdini/network/wire.html)); Simulink suggests the blocks "likely to come next" after the starting port and orders them by usage history ([R2018b](https://blogs.mathworks.com/simulink/2018/09/24/whats-new-in-r2018b/)); Qt Designer, when a connection is dragged onto empty space, ties it to a "ground symbol" and opens a dialog that disambiguates the signal and the slot ([Qt, Signals and Slots Editing Mode](https://doc.qt.io/qt-6/designer-connection-mode.html)); draw.io shows four blue arrows on hover, and clicking one clones and connects the shape ([draw.io](https://www.drawio.com/docs/manual/connectors/connect-shapes/)); Kaoto puts "+" on edge hover ([Kaoto](https://kaoto.io/docs/designer/02-working-with-nodes/)). The order of the gesture matters: *first* the gesture (where the new element will live), *then* the choice of type, in a menu at the drop point — EA and Cameo place the new element where the drag ended, which also solves "where does the new node appear" without a global re-layout, compatible with "positions belong to the user".

The second cluster is **legality visible before the click**. In Vivado, when you drag a connection, "a green check mark appears next to any compatible destination connections", and an interface connection is "a more prominent connection box" versus "a narrow connection line" for a signal ([UG994, Making Connections](https://docs.amd.com/r/en-US/ug994-vivado-ip-subsystems/Making-Connections)); in Platform Designer the *potential* connections appear as gray lines with a hollow circle, a click fills it, a click on the filled circle deletes the connection ([Intel](https://www.intel.com/content/www/us/en/docs/programmable/683609/22-3/connecting-system-components.html)); Blueprints shows the green check mark on the valid target and, on incompatible pins, "an icon will appear along with the reason why you cannot connect the nodes" ([Connecting Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/connecting-nodes-in-unreal-engine)); ComfyUI enforces "You can only connect ports of the same color" and highlights the compatible nodes while you drag a link ([ComfyUI links](https://docs.comfy.org/development/core-concepts/links.md)). Port typing pays off even without drag: in Blueprints the pins are outlined when unwired and filled when wired ([Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/nodes-in-unreal-engine)), and Blender encodes *structure* in the socket shape — circle, rectangle, diamond ([Blender Node Parts](https://projects.blender.org/blender/blender-manual/raw/branch/main/manual/interface/controls/nodes/parts.rst)). For verification, the normative vocabulary already exists: "The square box on the producer indicates a port and the circle on the consumer indicates the export", the analysis port is "represented as a diamond on the monitor", and active mode "requires that the agent instantiate a driver and sequencer" ([UVM 1.2 User's Guide](https://www.accellera.org/images/downloads/standards/uvm/uvm_users_guide_1.2.pdf)) — Ridgeway observes at DVCon that active and passive agents of the same class are visually indistinguishable unless you tell them apart explicitly ([DVCon 164](https://dvcon-proceedings.org/wp-content/uploads/164-Visualizing-SystemVerilog-and-UVM.pdf)).

The third is **automation that proposes, not one that does**. The Vivado banner and its dialog with per-element options, SmartDesign's "Auto Connect" for which "If a bus interface has multiple possible matches, Auto Connect makes no connection" ([Microchip](https://onlinedocs.microchip.com/oxy/GUID-6BACC19D-0959-4B51-87AC-AD97B0E07E35-en-US-1/GUID-40861B0B-584D-488C-82B3-AF82F54A6472.html)), Platform Designer's "Auto Assign Base Addresses", Android's "Infer Constraints" whose results "can be wrong and may need manual fixes" ([Techotopia](https://techotopia.com/index.php/A_Guide_to_using_ConstraintLayout_in_Android_Studio)) all say the same thing: users tolerate a dialog if the tool first *shows* what it will do and highlights the result afterwards. The limits are documented just as clearly — "Block automation is not re-entrant" ([UG994](https://docs.amd.com/r/en-US/ug994-vivado-ip-subsystems/Creating-a-Design-with-CIPS-IP)) — so proposals must be explicit, acceptable and rejectable, not silently materialized.

The fourth cluster is **in-place editing**: StarUML opens "Quick Edit" on double-click or Enter with a micro-syntax `[ "<<" stereotype ">>" ] [ visibility ] name` and per-type buttons ("Add Sub-class" instead of class + generalization) ([StarUML](https://staruml.readthedocs.io/en/latest/reference/quick-edits.html)); Papyrus does F2 with Xtext autocompletion ([Papyrus–Sirius](https://help.eclipse.org/latest/topic/org.eclipse.papyrus.sirius.doc/target/site/generated-eclipse-help/papyrus-sirius-userDoc.html)); Simulink allows you to "edit and tune parameters on the canvas without opening the block dialog" ([R2018b](https://blogs.mathworks.com/simulink/2018/09/24/whats-new-in-r2018b/)); ComfyUI renames on "Double click node title" and keeps the widgets on the node ([ComfyUI settings](https://docs.comfy.org/interface/settings/lite-graph)). Property sheets persist in every tool — the lesson is to keep them *secondary and synchronized*, not to eliminate them; the regression documented in Papyrus (edits from Properties that did not appear in the model) is exactly the class of bug that a single source of truth re-rendered on every change eliminates by construction.

The fifth is **state on the graph, not in a separate panel**: badges on the element (Houdini, Node-RED, Sirius Web — "small icons that can be positioned around a node using cardinal and ordinal directions", with a visibility precondition ([Obeo](https://blog.obeosoft.com/what-s-new-in-sirius-web-2026-5-and-2026-7))), broken wires (LabVIEW), a yellow element with a wrench icon that lists the fixes — "Create Port", "Reverse Direction of Port", "Navigate To" ([Cameo](https://docs.nomagic.com/x/GNp9B)), pass/fail/warn coloring from Model Advisor and edit-time checks restricted to a cheap subset ([Edit-time checking](https://www.mathworks.com/help/slcheck/ug/check-for-compliance-using-edit-time-checking.html)), inline icons in the tree with "Click the icon for details" (Android). The counter-example is Capella: markers persist as artifacts and "to clear the icons you must delete the markers in the problems view" ([Capella forum](https://forum.mbse-capella.org/t/show-hide-warning-messages/3702)) — markers must be *recomputed* from the source of truth on every change.

The sixth is **code next to the diagram, linked in both directions** (Embedded Coder, HDL Coder, Umple, Markdown preview), plus the "what will it generate" variant without persistence: MPS "Preview generated text" "does not persist the generated artefacts" ([MPS](https://mps-support.jetbrains.com/hc/en-us/community/posts/4408306494482/comments/4408332982418)); Data Wrangler generates pandas code per step, "Each step of the generated code can be modified" and exports it into a notebook cell ([VS Code, Data Wrangler](https://code.visualstudio.com/docs/datascience/data-wrangler)); FlutterFlow shows, under the properties panel, the generated constructor line, with "..." for the properties already set by the panel ([FlutterFlow](https://docs.flutterflow.io/resources/ui/widgets/properties)); Helm has "Preview Template" for the effective configuration ([vscode-kubernetes-tools](https://github.com/vscode-kubernetes-tools/vscode-kubernetes-tools)). The developers in the HN thread about Figma Dev Mode do not trust generated code they cannot *relate* back to the design — "I don't really see the use case for code export at scale" ([HN](https://news.ycombinator.com/item?id=36420712)) — which argues for *per-component* preview ("what does this box become"), not "export everything".

The seventh is **the structure of the inspector**: Android "Declared Attributes: attributes set in the file" at the top, then Common, then All; filled indicator = resource reference, hollow = hard-coded value ([Android](https://developer.android.com/studio/views/layout-editor)); Qt "Modified properties are indicated with bold labels. To reset them, click the arrow button on the right" and "Changes in properties are applied to all selected objects that have the same property" ([Qt, Widget Editing Mode](https://doc.qt.io/qt-6/designer-widget-mode.html)); NN/g — progressive disclosure "improves 3 of usability's 5 components: learnability, efficiency of use, and error rate" ([NN/g](https://www.nngroup.com/articles/progressive-disclosure/)). This cluster aligns literally with the "simple by default, powerful when needed" principle from docs/07 (SCOPE / RELEVANCE ⇒ hide / RARITY ⇒ "Advanced") — the research confirms its rules and adds two: *mark what is written explicitly* and *offer reset = delete the key*.

The eighth is **navigation and level of detail**: Simulink's "Explorer Bar" with clickable ancestors, Up to Parent / Back / Forward and a path editable as text ([Navigate Model Hierarchy](https://www.mathworks.com/help/simulink/ug/navigate-model-hierarchies.html)); Houdini H/G for framing, U to go up, Ctrl+1..5 "quick marks" ([Houdini shortcuts](https://www.sidefx.com/docs/houdini/network/shortcuts.html)); Blueprints renders with LOD depending on zoom (`GetCurrentLOD`) ([UE API](https://docs.unrealengine.com/4.26/en-US/API/Editor/GraphEditor/SNodePanel/GetCurrentLOD/index.html)); ComfyUI switches to "low quality" rendering below the 0.6 threshold ([ComfyUI settings](https://docs.comfy.org/interface/settings/lite-graph)); Capella recommends "break down your system into smaller diagrams" and filters in the toolbar ([Capella forum](https://forum.mbse-capella.org/t/capella-diagram-optimization-questions/10943)). The ninth is **secondary notation**: Blender frames "Moving the frame also moves all contained nodes" ([Blender Frame](https://projects.blender.org/blender/blender-manual/raw/branch/main/manual/interface/controls/nodes/types/layout/frame.rst)), network boxes and sticky notes in Houdini ([Houdini organize](https://www.sidefx.com/docs/houdini/network/organize.html)), groups in Node-RED — information "through means unrelated to syntax, such as layout or color" in Green & Petre's terms ([Cognitive dimensions](https://en.wikipedia.org/wiki/Cognitive_dimensions_of_notations)).

## Diagnosis: the "not visual enough" feeling is articulatory and evaluation distance, not a lack of drawing

Hutchins, Hollan and Norman define directness through two distances and a feeling of engagement: the *semantic* and *articulatory* distance across the gulf of execution, the distance across the gulf of evaluation, and the rule that "the feeling of directness is inversely proportional to the cognitive effort needed to operate and evaluate a system" ([Hutchins, Hollan & Norman](https://vis.csail.mit.edu/classes/6.859/readings/pdfs/Hutchins-DirectManipulationInterfaces.pdf)). Shneiderman calls for continuous representation of the objects and actions of interest, physical actions instead of syntax, and rapid, incremental, reversible operations whose effect is immediately visible ([Shneiderman 1997](https://www.cs.umd.edu/~ben/papers/Shneiderman1997Direct.pdf)); users "can evaluate results before completing an action" ([Wikipedia, Direct manipulation](https://en.wikipedia.org/wiki/Direct_manipulation_interface)). Applied to today's main gesture — lasso over pins, then the "Agent from selection" button in the sidebar, then a quick pick — the three criteria fall as follows. **The articulatory distance is large**: the action happens far from the object, on a *description* of it, in a side panel and in a modal dialog; the survey shows that exactly this route ("go to palette → find → drag back → connect", or its equivalent with button + dialog) is what makes editors feel form-driven, and MathWorks justified Quick Insert on exactly this argument. **The evaluation distance is large**: there is no continuous representation of the action — no rubber-band wire, no ghost of the agent being born, no legal target lit up — and the effect lands as a YAML edit the user sees only if the text editor is open, and as SystemVerilog code they do not see at all until `generate`. Reversibility and incrementality are already satisfied architecturally (surgical edits + native undo): **what is missing is "continuous representation of the action", and those are, happily, the cheapest additions**.

Green and Petre's cognitive dimensions framework names the concrete price. *Visibility/juxtaposability*: the YAML facts live in forms, not on the canvas — an active agent and a passive one look identical, `match`/`max_latency` are not visible, and the harshest criticism leveled at visual builders is exactly this: "it's some checkbox in one of the half dozen inspectors", which is why "Choosing to be explicit is my number one reason to do things in code instead" ([Sam Soffes](https://soff.es/blog/why-i-dont-use-interface-builder)). *Progressive evaluation* — "How easy is it to evaluate and obtain feedback on an incomplete solution?" ([Cognitive dimensions](https://en.wikipedia.org/wiki/Cognitive_dimensions_of_notations)): the `checkConfig` validations exist, but they are *post-hoc* (diagnostics, decorations), not *pre-emptive* (illegal targets dimmed during the gesture); the generator refusals that are not replicated show up only at `generate`, which for QuickUVM is the exact equivalent of the Interface Builder failure mode — "a bad automatic merge might not be noticed until runtime" ([Soffes](https://soff.es/blog/why-i-dont-use-interface-builder)). *Hidden dependencies*: the data flow exposes them — it is the strong point of dataflow notations over spreadsheets ([Auckland COMPSCI 732](https://cs.auckland.ac.nz/courses/compsci732s1c/archive/2010/lectures/732Lecture2.pdf)) — provided the wires are not hidden; `render=label` on high-fan-out nets is a good decision, but the literature warns that hiding wires in Grasshopper makes dependencies hard to follow ([McNeel forum](https://discourse.mcneel.com/t/change-wire-display-custom-preview-m-input/82232)), so the mode must remain explicit and reversible, which is already the case. *Secondary notation* is missing entirely: there are no user frames, notes or colors; the persisted positions are the only information the diagram carries beyond the model, and a rendering derived from the model without secondary notation is, structurally, a *report*, not a *drawing* — this is the "feels visual" ingredient that the notes identify explicitly. *Viscosity*: changes with knock-on effects (agent rename → coverage, scoreboards, vseq steps; wiring → passivation in other files) are handled by cascades in the mutations, which is correct, but the chain is invisible until generation — a preview of the pending edit would make it visible.

Two further results reinforce the diagnosis. Petre shows that the differences in effectiveness "lie not so much in the textual-visual distinction as in the degree to which specific representations support the conventions experts expect" ([Petre 1995](https://cacmb4.acm.org/magazines/1995/6/8808-why-looking-isnt-always-seeing/abstract)), and Moody finds that in notations "graphical conventions [are] often an afterthought" ([Moody](https://research.utwente.nl/en/publications/the-physics-of-notations-a-scientific-approach-to-designing-visua/)); Architect's audience consists of verification engineers who learned UVM from the Accellera guide, Doulos and Verification Academy, so they expect the square, the circle and the diamond, not UML text compartments — the TB view speaks a slightly foreign dialect. And a 2024 study on pairs of students finds that the tool shapes the strategy: "Pairs using the text-based PlantUML all drew every class first and added connections later, while pairs using the visual MagicDraw tool drew classes and their associations one after another" ([arXiv 2409.13656](https://arxiv.org/pdf/2409.13656)) — a "wire-first" gesture (drag from the pin, then choose what appears at the end) would change the way users *think* a bench, from lists of components to connections.

Just as important is what the problem is **not**. It is not rendering capability — netlistsvg and TerosHDL use the same elkjs + SVG stack. It is not fidelity — Architect is *ahead of* the VS Code tools in the survey, which replace the whole document or round-trip through JSON, and the loudest complaints about YAML tools are precisely about this: "Please STOP deleting comments in yaml" ([Obsidian forum](https://forum.obsidian.md/t/please-stop-deleting-comments-in-yaml/104082)). It is not manipulation — Kaoto, Workflow Studio and Composer do not persist positions at all, only the layout direction. Against the five clusters of criticism leveled at visual builders (hidden state, unreadable files, late errors, editing in two places, performance), QuickUVM is structurally sound on three; the two to guard actively are *hidden state* and *late errors* — and both are fixed with feedback on the canvas, not with free drawing. In the terms of Myers, Hudson and Pausch, the target is "a low threshold and high ceiling" ([CMU](https://kilthub.cmu.edu/articles/journal_contribution/Past_Present_and_Future_of_User_Interface_Software_Tools/6470303/1)): proposals and templates lower the threshold, inline gestures and the contextual palette raise the ceiling, without any of them touching the invariants. The "table stakes 2026" list extracted from React Flow, tldraw, JointJS, GoJS and yFiles confirms the inventory of gaps: present — pan/zoom, framing, minimap, marquee, persisted drag, flip, fold, context menus, drill-down, auto-layout, orthogonal routing, undo, diagnostics; missing — drag-to-connect with validation and snap radius, click-to-connect, reconnection by dragging the end, creation by drop on the canvas, in-place text editing, per-node toolbar, marquee modifiers, align/distribute/straighten, frames, LOD, keyboard focus ([React Flow](https://reactflow.dev/api-reference/react-flow), [tldraw](https://tldraw.dev/sdk-features/snapping), [GoJS](https://gojs.net/latest/intro/tools.html)).

## What we do not copy, and why

Diagramming frameworks remain rejected, and the research reinforces D22/D23 with new evidence: GLSP is server-authoritative and its undo must be re-wrapped as a `CustomDocumentEditEvent` ([VS Code Custom Editor guide](https://code.visualstudio.com/api/extension-guides/custom-editors)); the editors that adopted generic engines replace the whole document (draw.io, KIE) and have `TODO`s about it; draw.io's custom-editor integration "fails to open .drawio files in Cursor with an assertion error" ([Cursor forum](https://forum.cursor.com/t/draw-io-integration-plugin-fails-with-custom-editor-api-error/146441)); Sirius Web has migrated to React Flow, so it would bring React as a dependency. All the patterns above are implemented with `pointerdown/move/up` on SVG elements, CSS classes for states and a small state machine per tool — exactly as the libraries themselves implement them.

Drag from a palette onto the canvas must not be the main creation gesture. MathWorks declares it slower than Quick Insert, the MBSE family has converged on creation from selection, Kaoto does not offer it from the catalog, and in QuickUVM most components are *derived* from the DUT (agents from pins, probes from nets), not placed freely — the role of the palette is already played by the inferred ghosts and, after R12, by the proposals. The palette remains useful for the few free components (virtual sequence, VIP by reference), but it is low priority.

Two-way editing of the generated SystemVerilog code is not attempted. Apple withdrew the SwiftUI inspector after five versions; SCADE explicitly forbids modifying generated code and does not generate at all if the model is non-conforming ([Ansys forum](https://innovationspace.ansys.com/knowledge/forums/topic/efficient-development-of-safe-space-software-with-ecss-e-st-40c-and-ecss-q-st-80c-using-scade-suite/)); a benchmark on Papyrus, Modelio and Visual Paradigm shows that the round-trip scenario "with changes in model and code presented results with some gaps in model and code coherence" ([ISCTE](https://repositorio.iscte-iul.pt/bitstream/10071/23470/1/conferenceobject_80303.pdf)); UVMF needs a merge report for unrecognized `pragma` blocks ([Verification Academy](https://verificationacademy.com/forums/t/questions-on-alu-generator-user-guide/40776)). Provenance is free in QuickUVM because every diagram element maps onto a YAML path — the valuable move is *to show* provenance (hover → YAML range, hover → generated line), not to allow editing the SV from the diagram.

The JSON round-trip and reformatting are out: Workflow Studio loses comments through the YAML→JSON→YAML conversion, and users of tools that rewrite YAML explicitly ask for an off switch ([TrueNAS forum](https://forums.truenas.com/t/option-to-toggle-off-compose-yaml-auto-formatting/64541)). Explicit connection modes generate documented confusion — an OMEdit user asked for a three-state "Connect/Unconnect Mode" button ([OpenModelica](https://trac.openmodelica.org/OpenModelica/ticket/3483)) — so gestures anchor on the port's hotspot, without a mode. The modal properties dialog on creation is what EA lets you disable for "rapid modeling", and creation only from right-click is a real complaint at Visual Paradigm ([VP forum](https://forums.visual-paradigm.com/t/why-no-keyboard-shortcuts-to-create-attributes-operations-in-uml-diagram/15974)); the practical rule is that deletion and composition keep the modal (already the case), and addition does not require it when a safe default exists. Persisted markers (Capella) are not copied — findings are recomputed from the YAML on every change, as itemis CREATE does ("live checked during editing" ([Eclipse Marketplace](https://marketplace.eclipse.org/content/yakindu-statechart-tools))) and as `checkConfig` does today.

Nor the visual maximalism of Blueprints: the classic criticisms of visual languages — the Deutsch limit of roughly 50 primitives on screen, "spaghetti", weak abstraction ([Visual Programming Codex](https://github.com/eliemichel/visual-programming-codex/blob/master/criticisms.md)) — argue *for* the existing choices (orthogonal router, labels on high-fan-out nets, folding of generates, subenv boxes, drill levels) and against a single flat graph with all wires visible. Wires dimmed or hidden by default (Grasshopper) hide dependencies; projectional editing as the main surface requires understanding the tree and changes the users' error profile ([FSE 2016](https://gup.ub.gu.se/file/206790)); automation that silently materializes (Android Autoconnect, "confusing and error prone") contradicts the invariant "overrides belong to the user". Finally, everything that requires a simulator — live transaction streams, UML sequence diagrams, class members next to signals ([Siemens Visualizer](https://resources.sw.siemens.com/en-US/fact-sheet-visualizer-tm-debug-environment)) — lies outside the product; the projection of results (R25) is done from files, not from a process.

## Open questions

A few things cannot be decided from research and require verification in the code or a decision by the author. *The missing mutations*: is there an agent rename with cascade (the symmetric of `removeAgent`) and an "add pins to an existing agent" mutation? R14 and the drop-on-agent variant of R10 depend on them, and the hard part is the mutation, not the UI. *Materializing the ghosts*: "Accept" on an inferred proposal (R12) is blocked by the two sharp edges from docs/07 — materializing the whole inferred set and expressing absence through `analysis: {scoreboards: []}` — which must be designed before the ghosts become editable. *The position seed at drop*: placing the new node at the drop point assumes that `layout/snapshot` with total seeds (D21) accepts a new, pre-seeded element alongside the existing ones, without interactive ELK moving it; to be verified empirically, as was done with `scripts/_probe-flip*.mjs`. *The legality model in the webview*: which of the `checkConfig`/`deriveConnections` rules are cheap and deterministic enough for feedback during the gesture, and how do they reach the webview (on `config/full`, or computed on demand at `pointerdown`)? *Traceability anchors*: for R20, should the generator emit comments with the element id (the HDL Coder "Comment Based" style), or is the manifest plus a regex on the class name enough? It is a request toward the QuickUVM repo, to be probed empirically before design, per practice. *The context menu*: the custom SVG menu versus `contributes.menus.webview/context` with `data-vscode-context` attributes (native, themed, but less controllable) ([Contribution Points](https://code.visualstudio.com/api/references/contribution-points)). *The D23 line for secondary notation*: the frames and notes in the sidecar (R21) are "geometry that does not map 1:1 onto YAML" — exactly the re-evaluation condition from D23 — so an explicit decision is needed that they are *annotations of the view*, not *model*. *Webview forms after the toolkit's demise*: the Webview UI Toolkit has been archived since January 2025 ([microsoft/vscode-webview-ui-toolkit](https://github.com/microsoft/vscode-webview-ui-toolkit)); R13/R16 either stay on CSS variables + Codicons or adopt VSCode Elements (small Lit components) — that would be a dependency to justify in the journal.

Evidence gaps remain too, to be flagged honestly. There is no controlled study comparing form-based editing with canvas-based editing in model editors; the diagnosis is theoretical (Shneiderman, Hutchins et al., Green & Petre) and convergent with practice, not measured. No source confirms that Vivado draws DRC badges on the canvas (the documented validation is in dialogs and message lists), and the Microchip pages were cited from search excerpts, not from the official pages. No source documents dark-theme conventions for design canvases; the VS Code tokens remain the only guide. Breker/Perspec, Modelio, Dymola and LabVIEW were not covered. Given the project's validation style — tutorials walked through manually, with closing criteria — the appropriate measure for R1–R18 is one that Figma phrases as "Speed is a feature": the number of clicks, dialogs and panel switches per gesture, before and after, on the `yapp_router` tutorial.

## Conclusion

The research overturns the premise of the question: QuickUVM Architect does not have a deficit of *drawing* but of *directness*, and its architectural differentiator — every gesture is a minimal, comment-preserving edit, with per-gesture undo, in a YAML the user can also edit by hand — is precisely the thing that tools with far larger budgets have not solved and that their users ask for most loudly. This advantage is invisible today, because it lives in the architecture; the recommendations with the best value/effort ratio (R4, R15, R19, R20) make it visible, and the rest move the trigger and the feedback of the gestures to where the user is looking, without touching the mutations, the versioned protocol or the invariants.

The implication for the roadmap is a reordering, not an extension: before any additional schema parity, a "state on the canvas + link to the text" sprint (R1–R5) and then the "temporary wire" state machine that unlocks at once creation from a pin and connection with legality (R10–R11) would change the perception of the product more than any new field in the inspector. And because the gesture shapes the user's strategy, a "wire-first" Architect will not just be more pleasant — it will produce benches thought in terms of connections, which is exactly what the generator validates most strictly.
